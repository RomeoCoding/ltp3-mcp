# P9a deviations and findings

1. Reverses P3 deviation 1: `PeakEff` next to `NomEff` is no longer blocked. The efficiency radio decides
   (ORACLES.md), and a missing `EffType` means `NomEff`. `B-EFFICIENCY-MODEL` now needs `MatrixA` or
   `pLossSet`, or an `EffType` other than `True`/`False`.
2. `A-CURRENT-FALLBACK`, `W-NO-CURRENT`, `B-NO-EFFICIENCY`, `B-NO-RESISTANCE` are gone: a missing key is
   the GUI default. `A-CURRENT-MODE` is gone because the radio is confirmed (O4: `LoadType : False` =
   INominal, absent = IPeak). `current_mode="nominal"` with a missing `Inom` now reads 10 A, not `Ipeak`.
3. `EffType : True` = peak is an extrapolation from `LoadType` (one corpus use, `A-EFF-RADIO`).
4. Power voltage: no Min/Max radio key exists in the corpus (Power terminals only carry `Vout`,
   `VoutMin`, `VoutMax`, `IoutMax`), so Typ (file value or 12 V) is always used.
5. Limit checks (`W-VIN-RANGE`, `W-IOUT-MAX`, `W-DROPOUT`, `W-PLOSS-MAX`) run only on stated values; running
   them on defaults would add warnings that cannot be verified against older default sets.
6. Older-version defaults differ for the resistor. v3.6.8 writes `Resstnce : 0` explicitly (O4), so an
   omitted `Resstnce` in old files (15 resistors, versions 3.0.3 and 3.4.1) is not "0 omitted". In
   `i.MX7 96 Board - Arrow.ltp3t` (3.0.3, `ResType 2`, no `Resstnce`) the `<ORal>` header shows drops of
   0.5 mV at 0.5 A and 0.2 mV at 0.2 A, i.e. about 1 mOhm. The solver still uses 0 ohm (flagged
   `A-DEFAULT`, and that template disagrees with its header). One template is too little to change the
   table; a fresh v3.0.3 resistor would settle it.
7. Remaining `<ORal>` disagreements on complete tabs (70 templates) include a unit-string quirk (the header
   prints `5.5AmA` where `format_oral` prints `5.5mA`) and header lists that differ in length; not
   investigated here. 144 templates agree and are complete.
