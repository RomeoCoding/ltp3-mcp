# P7 deviations and SDK spike (MCP server)

## Spike: `mcp==2.3.0` (read from `.venv/Lib/site-packages/mcp`, then a throwaway server)
1. Server class is `from mcp.server import MCPServer` (`FastMCP` is gone). `@server.tool(name=, description=)`
   registers a function; the description defaults to the docstring; the input schema comes from the
   signature (pydantic), and a `dict[str, Any]` return gives `structured_content` plus a JSON text block.
   Sync tools run in a worker thread (`anyio.to_thread`), so shared state needs a lock.
2. In-memory testing exists: `from mcp.client import Client; async with Client(server) as c:` then
   `c.list_tools()` / `c.call_tool(name, args)` (legacy initialize handshake over an in-memory transport).
   `CallToolResult.is_error`, `.content[*].text`, `.structured_content`.
3. Errors: an exception inside a tool becomes `is_error=True` with the text `Error executing tool X`
   (the original text stays on the server and a traceback is logged to stderr); bad arguments become
   `is_error=True` with a pydantic message (no code). Returning a `CallToolResult(is_error=True, ...)`
   from the tool is passed through untouched, so `server.py` returns `{"code","message","hint"}` JSON text itself.
4. stdio: `server.run("stdio")` (sync; `anyio.run` inside). stdout is the protocol channel, so logging goes to stderr.
   JSON-RPC over stdin/stdout is newline-delimited; `initialize` -> `notifications/initialized` -> `tools/list` works.
5. `_Server.call_tool` overrides `MCPServer.call_tool` to map argument-validation and unknown-tool failures
   (raised before a tool body runs) to the same JSON error shape (`BAD_ARGUMENTS`, `UNKNOWN_TOOL`).

## Deviations from PLAN.md
1. Part addressing: `part_id: int` and `part_name: str` are separate optional arguments (exactly one);
   `set_property` takes `part_id`/`part_name` or `terminal`; `add_part` takes `near_id`. *Why:* a digit-only
   name would resolve as an id in `Tab.part`. Names are resolved in `server.py`, ids reach the editor as ints.
2. Extra error codes beyond section 4: `BAD_ARGUMENTS` (schema violation), `UNKNOWN_TOOL`, `INTERNAL_ERROR`
   (any other exception: reported without detail, logged to stderr). `ValueError` on read (empty file) maps
   to `PARSE_ERROR`, other `OSError` to `BAD_PATH`.
3. Codes not reachable through the tools: `WOULD_SHORT` (the editor never raises it, P4 deviation 5) and
   `UNPARSEABLE_ARGS` (a file whose tags cannot be split fails at `open_tree` as `UNPARSEABLE_ARGS`
   only when the tab line is malformed; no test constructs one). All other codes have a test.
4. `compare_trees`: the library has no per-tab arguments or solve delta. The server adds `tab_a`/`tab_b`
   (filters the changes by tab name) and `solve_delta` (b minus a of summed complete-tab totals, watts).
   `include_solve` supplies `results_a/b` built from `solve()` keyed `(tab_index, part_id)`.
5. `export_json` returns the P6 schema `ltp3-export` (not `ltp3-graph/1`), with `results` per part from `solve()`.
6. `save_tree`: serialises the editor's document and builds a fresh `Tree` before `safeio.save` (editor views go
   stale after inserts); passes `opened_sha256` only when the target is the file the tree was last read from or
   saved to; after any save the session baseline (path, bytes, sha256) is the saved file, so a second overwrite
   is not `STALE_FILE` and the tree is no longer dirty. Default target: `<stem>_edited[_n].ltp3` beside the
   opened project file, else the working directory (templates, new trees).
7. `new_tree` builds a skeleton (`<Vers>`, `<Tabs>`, `<Summ>`, `<DS05>`) from structure only, no template text.
   It stays EXPERIMENTAL until GUI check G1.
8. `close_tree` on a dirty tree reuses `VALIDATION_FAILED` (as PLAN says). Templates open editable; `read_only`
   is only the explicit flag.
9. `tests/test_session.py` was not created: `session.py` is exercised through the server tests (the task limits
   P7 files to `test_server.py`). `docs/TOOLS.md` was not generated (not in the allowed file list).
10. `Editor.remove_part` may raise `AssertionError` on wired capacitor/net parts (QA finding); the tool wrapper
    turns it into `INTERNAL_ERROR` and the tree is left as the editor restored it. No test removes such parts.
