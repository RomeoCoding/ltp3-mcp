# P5 deviations

1. Corpus: 260 of 261 templates validate with zero errors under the plan's rules. `Power Tree for
   ADGM1304.ltp3t` (tab 2) failed two: it holds wire ids 114 and 124 twice (FORMAT.md 5 lists this
   anomaly). 114 is an exact duplicate wire; the two 124s are a full 14:Output -> 25:Input wire
   lying over a junction trunk, so terminals 14:Output:1, 25:Input:1, 4:Input:1 and 25:Output:1
   each appear on two wires, and the junction {124,136,137} does not close on the "other" 124.
   Rule change, not a loosening for clean files: with a duplicated wire id, (a) a junction member
   is accepted when any copy of that id agrees on the clique and coordinate, and (b) wires with a
   duplicated id are not counted for `TERMINAL_MULTI_WIRE`. `DUP_WIRE_ID` (warning) still reports
   them. Consequence: a user-made duplicate id hides one multi-wire error behind a warning.
2. Validator codes are `Issue.code` strings of its own (`DANGLING_TERMINAL`, `NON_CLIQUE_JUNCTION`,
   ...), distinct from the section 4 tool error codes. A blocked save raises `VALIDATION_FAILED`
   with the first five issues in the message. Extra error codes beyond the plan's list: `STRUCTURE`
   (model cannot be built), `BAD_ARGS` (unreadable tag argument, e.g. a non-integer part id),
   `BAD_POINTS` (Points value not `(x,y)` pairs), `LINEBREAK` (from `Document.check`).
3. `TAB_ORDER` flags only a part or terminal after a symbol or wire, as the plan says; symbol after
   wire is not an error.
4. `IOUT_OVER` compares `IoutMax` with the summed Load `Ipeak` (else `Inom`) on the driver's net,
   scaled by `10**IpeakU`/`InomU`. Only direct Load consumers count (converter input current needs
   the solver), and nets with several drivers are skipped. It fires on 209 template nets because
   peak is a worst case; it is a warning only.
5. `save(..., opened_sha256=None)` skips the staleness check; the caller passes `Loaded.sha256` when
   overwriting the opened file. Overwriting any other existing file needs only `overwrite=True` and
   is covered by the backup. Plan 2.5 rule 3 ties the hash to "the opened file" and `safeio` has no
   session, so the session layer (P7) must pass it.
6. The temp file is `<name>.ltp3.tmp-<pid>` (full name kept, so `*.ltp3` globs never match it) and
   backups are `<name>.ltp3.bak-YYYYMMDD-HHMMSS[-n]`; `-n` avoids overwriting a backup made in the
   same second. A missing target directory raises `BAD_PATH` and is never created.
7. After `os.replace` the file is read back and compared with the bytes written; a mismatch raises
   `BAD_VALUE` (the backup is already in place). Not in the plan; cheap insurance.
8. Tests import the synthetic builders from `tests/test_validate.py` into `tests/test_safeio.py`
   (pytest's default rootdir import mode); P5 owns no other shared test file.
