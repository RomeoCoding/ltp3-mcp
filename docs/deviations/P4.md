# Deviations from PLAN.md: P4 (editor and layout)

1. API is an `Editor(document)` class (`set_property`, `rename_part`, `add_part`, `remove_part`,
   `connect`, `disconnect`, `move_part`, `serialize`, `tree`) plus `changed_lines(before, after)`,
   not free functions. Model views hold block indices that every insert or remove shifts, so
   `Editor` rebuilds `tree` after each mutation and callers must re-read it (`add_part` returns a
   view of the fresh tree). Internally all line edits go through tag-line identity captured before
   the edit (`_block_of`), never through a stored `Block`.
2. Every public mutation is atomic: it ends with `Document.check()` and on any error the lines are
   restored from a serialized snapshot taken at entry. `Document` object identity is kept.
3. `connect` adds a branch to the far-end junction when the driver's wire already ends in one
   (Artix-7 `1:Output:1`: wires 10/18/19 gain one more member, no second junction). PLAN.md 2.4
   covers this under "adding to an existing junction"; the split on the first segment is used only
   when the far end is a plain terminal.
4. In a split, the old wire keeps its id as the trunk and both branches are new (as in PLAN.md's
   Artix-7 test). The junction sits `snap(L/2)` (at least 5, at most L) from the driver along the
   first segment. The new branch leaves it perpendicular to that segment.
5. `WOULD_SHORT` is never raised by `connect`: the sink must be an unwired Input, which belongs to
   no net, so a connect cannot join two driven nets. The code is kept in the vocabulary for P7.
6. Wire removal: a junction left with two wires and no Aux terminal is merged (the earlier wire in
   the file keeps its id, collinear points are collapsed); a junction left with one wire and no
   terminal deletes that wire too, repeatedly (the "lone branch" reading of PLAN.md 2.4). Removing
   a part restores the exact original bytes after `add_part` + `connect` (tested on the Artix-7
   sample and on all 261 templates).
7. `layout.place` also treats existing wire segments as obstacles (PLAN.md only names parts), and
   leaves a 100-unit column gap to `near`.
8. Anchor tests: the y rule is checked for parts of every type except `Net`, whose terminals sit on
   the top or bottom edge (FORMAT.md 5.1). x is checked on every wire end with a terminal.
9. `set_property` rejects keys not seen for the owner type (FORMAT.md 3 tables) unless
   `allow_unknown_key`; a key already present in the file is always editable. Only `Comments` and
   `Title` accept `\n` (stored as `*^!#`); `PartNumb` and all other values reject CR and LF.
   A numerically equal value (`"3.30"` vs `3.3`) is a no-op.
10. Fuzz tests tolerate the one corpus tab whose Input terminals already carry two wires
   (byte-identical duplicate wires in `Power Tree for ADGM1304.ltp3t`); the edit must not add to
   such a terminal, but the pre-existing condition is not an error.
